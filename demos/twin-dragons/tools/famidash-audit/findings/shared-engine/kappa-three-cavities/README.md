# Kappaclysm: three additional closed cavities

Ordinary Dissonance inputs enter three outlined, noncolliding cavities in the
early wave section. Bank-aware FCEUmm reads confirm the entries on the official
release and current upstream. Rendered original views and source review identify
closed terrain, no internal sprites and no nearby coin objectives. These are
separate from the earlier 42-cell Kappaclysm proposal.

The source proposals change only 11 fill cells: `(133,17)`, columns 140–141 at
rows 17–20, and `(118,18..19)`. They use existing solid left/right variants.
No physics code changes. The manifests pin each source revision and every
before/after file hash; the edit specs retain exact cells and GIDs. Apply the
matching source patch, regenerate A (and current HUGE), and build. Only the
Kappaclysm compressed payload changes, growing ten bytes in each export.

QuickNES and FCEUmm agree on all six unchanged-approach negative checks, with

fixed deaths and every preceding gameplay observation, excluding physical level
identity. The current witnesses come from fresh original-ROM Dissonance round

retimed into negative proofs.

Fresh Dissonance rounds 73 and 78 provide two clearing controls per source
version. FCEUmm verifies all four complete traces. Their identical inputs and
entire traces also complete unchanged on their original ROMs. Full bank-aware
review finds zero entries into the three original cavity footprints and zero
source mismatches. Section probe counts are 175/174 release and 179/175 current.
The current second control preserves Coin3. Other cavities and intended routes
remain under review; these are section controls, not whole-route qualification.
Mesen HUGE completes the 4765-frame current control without retiming, with only
two intro differences and physical level identity differing from standard.

Release A and current A/HUGE compile. Decoded geometry matches all 43 release A,
45 current A and 173 current HUGE levels. The release exporter initially
reallocated banks beyond capacity; retaining both original data and sprite bank
allocation files allows the small edited payload to link. Generated allocation
files are deliberately excluded from the source-only proposal.

This is a reviewed, narrow data repair. Connected fill regions alone cannot
establish that a region should be solid: the protected Electroman Coin3 corridor
is a counterexample. Further level repairs need original-ROM reproduction,
actual collision reads, source/objective intent review, paired negative and
clearing inputs, and export/build checks. No global fill-to-solid rule or clean
round is implied by this packet.
