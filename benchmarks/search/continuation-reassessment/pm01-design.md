# PM01: qualify complete physical-frame accounting

PG01 qualifies the guarded-progress mechanism, not its discovery utility. Before
comparing it at matched physical work, audit the cost components and check the
accounting against a whole-target measurement independent of admitted results.
The retention rule, projection, action law and ordinary policies stay fixed.

## Source identity

The successful coordinator admits every reserved job before closing the scoped
worker pool. Each job's clock delta surrounds `execute_job`, including snapshot
restore, replay-prefix actions and the new suffix. Bootstrap/import work is also
charged by a target clock delta. Metroid's report materialization does not create
or step a target. Completed campaign replay uses one target and checks every
recorded job's frames. Thus the missing component for a clean snapshot-root run
should be constructor setup, not a new estimate of action counts.

For W workers and the ordinary 929-frame genesis, the prediction is:

```
search engine physical = admitted search frames + (W + 1) * 929
replay engine physical = admitted replay frames + 929
whole caller physical = direct helpers + search engine + replay engine
```

This is conditional on successful construction, a fully drained run and the
pinned Metroid adapter's clock behavior. QuickNES starts its lifetime clock at
zero, advances it once per explicit frame, preserves it across restores/reset,
and never runs a frame during destruction. Constructor/load CPU work outside
explicit emulated frames still belongs in process wall/CPU measurements. A failed
constructor may perform work without returning its clock; it remains unknown.
The source-inferred formula does not retroactively manufacture measured receipts
for historical experiments.

## Independent counter and failure behavior

The generic optional meter brackets every actual bootstrap, worker and replay
target lifetime. Its commutative counters are outside all deterministic state;
there are no per-frame mutex operations and no added reads when omitted. It sums
initial clock values and closed post-constructor deltas exactly once. The caller
records separate phases even when the engine returns an error. Live targets,
failed construction, arithmetic overflow, observed clock regression/saturation
and a poisoned meter cannot yield a complete total. External termination may
prevent a final receipt. The meter is not a live stopping mechanism, and host
measurement overhead can affect a wall-time cutoff.

The finite generic fixture supplies nonzero constructor work. It compares exact
streams, reports and checkpoints with measurement on/off for one/four workers and
both result-buffer sizes. A writer that fails before any job record verifies that
executed work still survives in the closed receipt. Restore/reset, live receipt,
regressed/saturated clock and arithmetic/incomplete-receipt cases are checked.
The native caller's arithmetic test rejects double-counting and incomplete costs.
