# RR02 source contract: reconstruct, compare, then inspect

RR01's incompatible import remains closed. This distinct procedure regenerates
the exact already-searched prefix on ms02 through ordinary execution. Source
qualification has passed ten tests and strict Clippy with the original AP01
motion/context features. No emulator allocation is made by these source results.

For fixed original/runtime core hashes, the comparison accepts two snapshots
only when their complete observation/terminal metadata agree, both headers have
the pinned magic/revision and a correct state length, each embedded core hash
matches its independently pinned build, and all bytes outside that 64-byte field
agree. The comparison reads serialized values and never modifies either snapshot.
For a given original snapshot and runtime hash, these constraints permit at most
one corresponding complete runtime snapshot value. They do not prove that a
different native build will actually produce that value.

Counterexamples reject payload changes, wrong or swapped core hashes, changed
revision/magic/length, truncation, trailing bytes, changed or missing metadata,
and missing, reordered or renamed checkpoint entries. The exact saved 3,314-action,
117,875-frame prefix passes the source decoder; changed hashes/counts fail. A
source fixture verifies that reconstruction requires the recorded prefix hash,
reserves its work in addition to the divergent-job bound and changes only the
runtime backend and actual generated-origin hashes in the derived header. The
selected original job bytes remain identical. The frozen RR01 request still
fails before stream parsing or target creation.

Native qualification would regenerate the root, check all its bytes under the
relation, verify its live context and replay exactly four original jobs/865
frames. Only a same-executable/input qualification would permit full replay.
That phase independently regenerates the same runtime root/origin, checks all
2,548 jobs and their original frame/digest/admission records, and compares every
one of the 588 final cached snapshots under the same relation before finishing
the 3,770-row competition capture. Failure stops the new protocol without retry,
changed bytes, replacement inputs, longer horizon or policy promotion.

Directly owned setup/prefix work has periodic and failure counter receipts.
The generic replayer still does not expose its constructor or incomplete work
after an error; preserve that unknown and its prospective physical upper bound.
Save generated root/checkpoint artifacts before comparison so a mismatch can
be inspected without emulation. A new registration must pin the built executable,
all inputs, fixed query, scripts, wall/memory/output/CPU limits and total budget.

The query is unchanged: count comparable local losses of lower qualified boss
HP in both rejection/replacement directions, with resource equality separate
and unavailable context left unknown. However, evidence is explicitly local to
the **reconstructed ms02 campaign**. Historical job digests omit full emulator
bytes and boss HP, and final checkpoints do not contain every discarded state.
Passing the known-artifact checks does not prove identity of all those missing
ARM states. A positive result could support a paired continuation counterexample
using the actual captured runtime states; it does not establish historical loss,
lifetime damage, boss defeat, global recoverability or fresh-search improvement.

No fresh search, new policy, MM2 transfer or untouched validation is allocated.
The full matched boss/Wily goal remains active. msr1 is unavailable.
