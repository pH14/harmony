# `harmony-linux`

The first pluggable guest-environment tier: pinned Linux kernels and images,
guest-resident agents, and the internal no-std wire SDK. The engine's bare-metal
acceptance workloads and their goldens live at `consonance/acceptance-suite`, not
here; that carve-out keeps product tests with consonance while keeping OS policy
out of the deterministic substrate.

## Entry points

```sh
make -C consonance/harmony-linux fetch             # fetch and hash-check pinned sources
make -C consonance/harmony-linux libvoidstar       # clean-room compatibility library
make -C consonance/harmony-linux test-libvoidstar  # ABI + device-transaction unit gate
make -C consonance/harmony-linux test-linux        # Linux reproducibility + boot gate
make -C consonance/harmony-linux test              # library gate, then Linux gate

make -C consonance/acceptance-suite test-payloads  # portable acceptance gate
```

Linux artifacts land in `consonance/harmony-linux/build/`. Native build trees use the fixed
path `/tmp/harmony-linux-build` (override with `GUEST_BUILD_ROOT`). Task 43 changed
the old hashed path and kernel build identity only because `/dev/harmony` already
requires a kernel rebaseline; `linux/MANIFEST.sha256` is therefore regenerated by
the twice-reproducible Linux gate rather than silently retaining old hashes.

## Locked release images

The repository-root `flake.nix` and `flake.lock` are the release-image build of
record. On native Linux/x86_64 they produce the minimal x86 image; on native
Linux/aarch64 they produce the minimal, NES, and PostgreSQL ARM images. Every
source and tool is supplied by the locked Nix graph, Cargo is offline, and the
output directory includes a freshly generated `MANIFEST.sha256`:

```sh
nix run .#guest-images -- --output "$PWD/guest-output"
nix run .#guest-images -- --output "$PWD/guest-output" --rom /path/to/smb.nes
```

The x86 CI lane adds `--serialization-gate` so the positive KUnit boot and its
deliberately unlocked negative run while the locked kernel source and object
tree still exist. The option is x86-only and requires `qemu-system-x86_64` on
the host.

The ARM form requires root while assembling the owned PostgreSQL filesystem and
admits the ROM only at the frozen SHA-256. The destination must be empty. The
imperative entry points below remain useful developer gates, but their output is
not N5 release evidence.

The AA-5(c) ARM spike has separate native Linux/aarch64 entry points (validated
on the `msr1` build host):

```sh
make -C consonance/harmony-linux arm64-image
```

They require Linux/aarch64 and publish `Image` plus `initramfs.cpio.gz` under
`consonance/harmony-linux/build/arm64/`, so they cannot overwrite the established x86
artifacts. The kernel build applies the pinned `patches/arm64/` virtual-time-clock
and LSE-only patches and refuses publication unless the final `vmlinux` and vDSO
contain zero live generic-counter reads and zero LL/SC reservation-monitor
instructions. The initramfs contains one freestanding syscall-only `/init` (no
libc or BusyBox), built with LSE-only compiler flags and scanned by the same AA-4
gate. These artifacts are spike evidence, not an AA-5 certification by themselves;
the live pinned-box gates remain authoritative.

## Linux prerequisites

On Debian/Ubuntu:

```sh
apt-get install -y build-essential flex bison libelf-dev libssl-dev bc cpio \
  kmod wget qemu-system-x86 xz-utils bzip2 shellcheck
```

On macOS, run the Linux gate in a Linux/amd64 container as documented in
`docs/BUILDING.md`; it fails fast instead of skipping. The compatibility-library
gate itself is portable and uses the host C compiler.

## Environment-owned components

- `linux/` pins and builds the kernel and all reproducible initramfs variants.
  Its built-in `/dev/harmony` driver serializes the fixed hypercall pages, stamps
  pid/comm/userspace-RIP attribution, emits JSON synchronously, and obtains seeded
  entropy with a one-byte-write/eight-byte-read transaction. Its bounded
  raw-frame ioctl is the sole x86 agent path, so agents share the same critical
  section and never map the doorbell pages or obtain I/O privilege.
- `libvoidstar/` is a clean-room implementation of the SDK-facing dynamic ABI.
  It never falls back to host entropy; device failures drop an event or return zero.
- `sdk/` is internal binary-wire plumbing for bare-metal payloads and guest agents.
- `play-agent/` and `tetanes-agent/` are Linux workload agents and remain
  standalone Cargo workspaces.

Pins, image-specific prerequisites, boot arguments, and determinism rationale are
recorded in `linux/versions.lock` and `linux/IMPLEMENTATION.md`.
