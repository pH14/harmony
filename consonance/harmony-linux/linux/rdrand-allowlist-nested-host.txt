# Hardware-RNG (rdrand/rdseed) per-site allowlist for the guest kernel as built
# by ms02 GCC 14 with the nested-host configuration — the
# nested-host counterpart of the ordinary kernel baseline, for the same reason
# as the rdtsc lists (offsets and inlining are toolchain-dependent).
# Every entry is a site the review confirmed sits behind an
# X86_FEATURE_RDRAND / X86_FEATURE_RDSEED check: the frozen CPUID (stock
# virtual_time composition) hides both features, so a checked site is dead code
# in the image; an unchecked site would execute natively (SVM cannot intercept
# the instruction) and feed true entropy no contract can replay.
# Selected by NESTED_HOST_PROFILE; HARMONY_RDRAND_ALLOWLIST selects other toolchains.

# extract_entropy's block loop tries arch_get_random_seed_longs (rdseed) then
# arch_get_random_longs (rdrand); both inlines check the instruction on
# static_cpu_has(X86_FEATURE_RDSEED / X86_FEATURE_RDRAND).
vmlinux:extract_entropy.constprop.0+0xa0
vmlinux:extract_entropy.constprop.0+0xb3

# random_init_early's seeding loop, same seed-then-random inline pair, same
# static_cpu_has gating.
vmlinux:random_init_early+0x3a
vmlinux:random_init_early+0x4e

# The RDRAND self-test; its first statement returns unless
# cpu_has(c, X86_FEATURE_RDRAND).
vmlinux:x86_init_rdrand+0x17
