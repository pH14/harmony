# x86 guest CPU contract

This directory defines the x86 CPU surface presented to a Harmony guest. The
contract fixes CPUID values, classifies MSR reads and writes, specifies modeled
timer and interrupt behavior, and supplies the constants included in the
snapshot contract hash.

## Files

- `intel.toml` is the active `GenuineIntel` contract used by `vmm-core`.
- `amd-draft.toml` is parsed and validated by tests but is not available to a
  live VM construction path.
- `baselines/cfl/` contains the captured Coffee Lake values used to derive the
  Intel model.

The TOML files are the contract authority. `vmm-core` embeds them at compile
time, parses them through `vendor::x86::contract`, and derives the CPUID model,
MSR filter, access dispositions, and contract hash from the parsed values.

## Runtime use

The active contract is installed before the first guest entry. CPUID leaves not
listed by the model return the contract's default value. MSR indexes are
classified as guest state, fixed values, virtual-time emulation, ignored
writes, or guest faults. The backend installs the resulting KVM policy; the
architecture-neutral engine consumes the derived values through the backend
interface.

The AMD file remains a draft until its values and enforcement mechanisms are
qualified on a supported host. Its constructor and embedded bytes are compiled
only for tests.

## Updating a contract

A contract change includes its schema/version decision, canonical bytes, and
committed hash. The focused tests validate parsing, disjoint index sets, vendor
identity, canonical serialization, and agreement between the computed and
committed hashes:

```sh
cargo test -p vmm-core contract::tests
```

The ignored regeneration tests print canonical files for review. Run them only
when intentionally changing a contract:

```sh
cargo test -p vmm-core contract::tests::regen_golden -- --ignored --nocapture
cargo test -p vmm-core contract::tests::regen_amd_golden -- --ignored --nocapture
```

Review generated bytes and update the corresponding `contract_hash` field in
the TOML rather than treating the generated output as an independent source of
truth.
